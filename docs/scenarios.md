# Пользовательские сценарии

Путь сотрудника: **найти информацию → понять применительно к своей ситуации → перейти к действию**.

## С1. Вопрос по Инструкции своими словами

> «Пришёл бумажный оригинал документа, который уже зарегистрирован в электронном виде. Регистрировать заново?»

1. Классификатор: вопрос. Гибридный поиск с фильтром по роли находит п. 5.2 (и близкие пункты) с процентом релевантности.
2. Ответ: «Простыми словами» (модель, только по п. 5.2, с проверкой) → «Как в документе» (цитата п. 5.2) → «См. также» → источники (документ, ред. 1.0, дата, пункт, глава, %). Кнопка «📄 Тексты пунктов» показывает полные тексты.
3. Уточнение в контексте: «а если оригинал пришёл через неделю?» — вопрос дополняется предыдущим.

## С2. Найти нужное место

> «пункт 8.12.4», «покажи приложение 1», «в каком пункте сказано про гриф согласования?»

Пункт по номеру — точное совпадение (100 %), показывается только он. Остальное — обычный поиск с указанием пунктов.

## С3. С кем согласовать (Матрица визирования)

> «С кем его нужно согласовать?» (после вопроса о рабочей группе)

1. Бот не угадывает вид документа и задаёт **один** уточняющий вопрос с кнопками «Приказ / Распоряжение / Письмо».
2. Тему (рабочая группа) берёт из контекста диалога → строка 6 Матрицы.
3. Ответ кодом: ✅ Департамент ДОУ, ✅ Кадровое подразделение, ⚠️ Департамент ИТ — если ИТ-проект; срок рассмотрения 3 рабочих дня (п. 10.3); порядок визирования (п. 10.6); правило п. 3 Матрицы о совокупном применении строк.

## С4. Сроки

> «Сколько дней на согласование?» → «Срок зависит от вида документа. Уточните…» → [распоряжение] → «3 рабочих дня (п. 10.3)».
> «Какой срок исполнения обращения гражданина?» → «30 календарных дней (п. 6.6)» + срочные документы (п. 6.7).

Срок конкретной датой — [С14](#с14-сроки-датами-калькулятор-сроков).

## С5. Подготовить документ по шаблону

> «Нужно подготовить распоряжение о создании рабочей группы»

1. Шаблон подбирается по ключевым словам. Если неоднозначно — LLM, затем список шаблонов кнопками.
2. Сразу показываются согласующие из Матрицы (строка 6).
3. Вопросы по очереди («Вопрос 3 из 12»), с подсказкой из примечаний модуля и примером. Есть значения по умолчанию, кнопки «Да/Нет», «Пропустить», «Оставляю за собой». Работают команды «назад» и «отмена».
4. Валидация: дата («15 декабря» → «Не удалось распознать дату…»), ФИО с инициалами, список участников, «Подразделение — должность И. О. Фамилия».
5. Готовый .docx (оформление модуля сохранено, служебные элементы удалены по п. 3.3 метод. рекомендаций) + список заполненных полей + итоговые согласующие + чек-лист требований со ссылками на пункты + следующий шаг (РК, «Примечание» по п. 2.3 метод. рекомендаций).

Доступные шаблоны: приказы о вводе ИС в эксплуатацию, о назначении ответственных за делопроизводство, о приёме и передаче дел и имущества, об утверждении локального акта; распоряжения о внутреннем аудите, о проектном комитете, о рабочей группе.

## С6. Проверить свой черновик

Загрузка .docx/.pdf (скрепка или drag&drop) → отчёт: тип документа, распознанный модуль, ❌ замечания / ⚠️ предупреждения / ✅ соответствия, у каждого — пункт и рекомендация, плюс подсказка по обязательным визам.

## С7. Нет ответа в базе

> «Какая зарплата у главного специалиста?»

«В базе знаний недостаточно информации…» + куда обратиться (Департамент ДОУ, п. 2.1 и 4.1.3). Для тем «доступ/ИИС ДО/кадры» подставляются ДИБ (п. 2.5), координаторы ИИС ДО (п. 2.7), кадровое подразделение (п. 9.6). Вопрос пишется в лог вопросов без ответа для пополнения базы.

## С8. Куда обратиться

> «Куда обратиться по вопросу доступа к ИИС ДО?» → Департамент информационной безопасности + текст п. 2.5.

## С9. Разграничение доступа

Учётная запись с ролью «Сотрудник»: вопрос про шифрование ИОД не находит закрытый п. 2.11. Ответ строится только по общедоступным пунктам или даётся отказ. Роль «Администратор» получает п. 2.11, может включить поиск по архивным редакциям и работает в админ-панели (учётные записи, журнал, оценки, новости, редакции). Роль задаётся в учётной записи, выбрать её в интерфейсе нельзя.

## С10. Администратор: новая редакция

Админ-панель → «База знаний и статус» → «Загрузить новую редакцию» (или `scripts/ingest.py --doc … --version 1.1 --date …`) → индексация в фоне, дифф пунктов, новость о редакции в ленте портала. Прежняя редакция уходит в архив, работающий бот отвечает по новой и ссылается на «ред. 1.1 (с 15.01.2027)». Откат — «Сделать действующей» у архивной редакции.

## С11. Администратор: новый документ

Админ-панель → «Добавить документ»: «Регламент работы с электронным архивом», доступ «Ограниченный», файл .docx → индексация в фоне. Администратор спрашивает «В каком формате электронный архив принимает дела?» и получает цитату «Регламент архива, фрагмент 2 — разд. «Формат и сроки приёма»». Сотрудник тот же вопрос не находит в новом документе, не видит его на портале и в ленте. «Отключить» убирает документ из поиска.

## С12. Помощник на портале организации

Портал подключает виджет одной строкой `<script src="https://<помощник>/widget.js" defer></script>`. Сотрудник, вошедший в помощника, открывает окно кнопкой в углу любой страницы портала и спрашивает; Esc или × закрывает окно. Сайт, которого нет в `portal.embed_origins`, чат не покажет.

## С13. Живая речь

Сотрудник пишет как в мессенджере, с опечатками и без официальных терминов:

| Сотрудник | Помощник |
|---|---|
| «скока дней на согласавание приказа» | «_Исправил опечатку: «согласавание» → «согласование»._» Срок 10 рабочих дней (п. 10.3) |
| «когда регать входящее письмо?» | Простыми словами: в тот же день, вечером или в выходной — не позднее следующего рабочего дня. Как в документе: п. 5.6, 91 % |
| «а исходящий?» | «_Понял вопрос так: «когда регистрировать исходящее письмо?»_» — п. 7.1 |
| «не понял» | «Попробую проще: …» — те же пункты, короче |
| «спасибо» | «Пожалуйста! Если появятся ещё вопросы по документам — пишите.» Без поиска и без отказа |
| `rjulf htubcnhbhjdfnm d[jlzobq ljrevtyn` | «_Текст был набран в английской раскладке — прочитал как «когда регистрировать входящий документ»._» |
| «можно ли подписаться за начальника, если он в отпуске?» | п. 8.19.4: при отсутствии подписанта подписывает исполняющий обязанности или уполномоченный заместитель («в отпуске» + «подписать» → термины пункта по `colloquial_terms`) |
| «письмо пришло не по адресу» | п. 5.14 о передаче документа в ответственное подразделение («не по адресу» → «некорректная маршрутизация» по `colloquial_terms`) |
| «мне надо создать рабочую группу, каким документом это оформить?» | Распоряжение (п. 9.7.1) и «Могу сразу подготовить черновик…» с кнопкой |
| «да» | Заполнение шаблона, вопрос 1 из 12 |
| «а что тут писать?» | Подсказка и пример к текущему вопросу, заполнение продолжается |

Если ответ не тот, сотрудник пишет «не то»: оценка 👎 уходит в журнал, а помощник показывает кнопками другие найденные пункты. Подробнее: [search_and_answering.md](search_and_answering.md#живая-речь).

## С14. Сроки датами (калькулятор сроков)

> «Если отправлю распоряжение на согласование сегодня, когда будет готово?»

1. Намерение «расчёт срока» (`deadline_calc`) — по словам «когда будет готово», «к какому числу», «до какого числа», «крайний срок», «когда истекает», «через сколько дней» или по дате отправки с вопросом «когда». Вопрос о сроке без даты («сколько дней на согласование?») остаётся прежним сценарием С4.
2. Из вопроса код берёт вид документа (строки п. 10.3), дату отправки («сегодня», «завтра», «во вторник», «12 ноября», «15.11», с опечатками) и этап: согласование (по умолчанию), рассмотрение, исполнение, подписание. Нет вида документа или даты — **один** уточняющий вопрос с кнопками; если нет ни того, ни другого — один вопрос сразу о двух («Распоряжение, сегодня»), плюс кнопка «Только срок в днях».
3. Ответ: **итоговая дата** → таблица «этап / кто / срок в рабочих днях / крайняя дата» → как считал и предупреждения → **основание** (документ, редакция, пункты, строка Матрицы) → **простыми словами** → предложение черновика, если для документа есть модуль.

| Сотрудник (сегодня — сб, 24.10.2026) | Помощник |
|---|---|
| «Если отправлю распоряжение на согласование сегодня, когда будет готово?» | Итог: рассмотрение завершится не позднее **ср, 28.10.2026** — 3 рабочих дня (п. 10.3), подразделения рассматривают одновременно (п. 10.2); отсчёт с понедельника, потому что суббота нерабочая. Таблица: первичное рассмотрение (Юридическое подразделение, Департамент ДОУ — Матрица, строка 7), повторное рассмотрение, визирование по очереди (срок в Инструкции не указан), подписание (3 рабочих дня, как правило) |
| «а если приказ?» | Та же дата отправки, 10 рабочих дней: **ср, 11.11.2026** (4 ноября не считается) |
| «Когда истекает срок рассмотрения, если отправил 12 ноября?» | Уточняющий вопрос «какой документ» с кнопками; после «Распоряжение» — **вт, 17.11.2026** |
| «К какому числу согласуют приказ, если отправить 30.12.2026?» | **пт, 22.01.2027**: 31 декабря и 1–10 января не считаются; предупреждение, что календарь на 2027 год предварительный |
| «До какого числа ответить на обращение гражданина, если его зарегистрировали 12 ноября 2026?» | 30 календарных дней (п. 6.6) истекают сб, 12.12.2026 — срок переносится на предшествующий рабочий день: **пт, 11.12.2026** (п. 6.4) |
| «Когда истекает срок визирования приказа, если отправил сегодня?» | «**Срок визирования в базе знаний не указан**» — п. 10.6 задаёт только порядок; куда обратиться (Департамент ДОУ, п. 2.1) и кнопка «Посчитать срок рассмотрения» |
| «К какому числу согласуют распоряжение, если отправить 12 ноября 2030?» | Дата по одному правилу выходных и предупреждение «праздничные дни за этот период не учтены» — 2030 года в календаре нет |

Даты считает код по производственному календарю (`app/approval/calendar_ru.yaml`), сроки — из текста пунктов; модель в расчёте не участвует ([search_and_answering.md](search_and_answering.md#сроки-в-датах-код-а-не-модель)).
