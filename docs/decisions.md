# Решения, принятые самостоятельно

Решения по неоднозначностям и отклонениям от PLAN.md, с обоснованием.

| # | Вопрос | Решение | Почему |
|---|---|---|---|
| D-01 | В `data/` **нет файла «Примеры пользовательских запросов»** (PLAN.md, раздел 2) | Набор вопросов составлен самостоятельно по тексту Инструкции разговорными формулировками: `tests/eval_questions.yaml` (29 вопросов для настройки + 12 вопросов контрольной выборки) | По PLAN.md нужно остановиться и сообщить, но задача требовала работать без остановок. Вопросы помечены как синтетические. **Когда появится реальный файл, его нужно добавить в eval и перепроверить порог** |
| D-02 | Запуск Ollama: Docker или нативно | По указанию пользователя Ollama работает **нативно на macOS** (GPU/Metal). Одна команда запуска — `./run.sh`. Демо-стенд на Ubuntu тоже без Docker: две службы systemd (`ollama` и `dou-assistant` с `run.sh`) за Caddy. `docker-compose.yml` (сервисы `app` + `ollama`) написан для Linux-сервера | Docker не установлен ни на машине разработки (установка была отклонена), ни на сервере, поэтому `docker compose up` **не проверялся**. В Docker на macOS нет доступа к GPU |
| D-03 | Модель | `qwen2.5:1.5b-instruct` (указание пользователя), задаётся в `config.yaml` → `llm.model` | Замер на Mac (Metal): ~190 ток/с, пояснение 0,2–0,8 с. На сервере без GPU ответ в среднем 3,9 с. Слабая модель, поэтому логика перенесена в код (D-12–D-15) |
| D-04 | Эмбеддинги | `bge-m3` через Ollama (`/api/embed`), без torch/sentence-transformers | Модель лёгкая (1,2 ГБ), запрос эмбеддинга — десятки мс, качество на русском хорошее. Переход на `multilingual-e5-small` не понадобился |
| D-05 | Уровни доступа: в исходных документах грифов нет | Уровни `public < internal < confidential`; все документы — `internal`. **Для демонстрации** разграничения доступа пункты 2.11 (шифрование ИОД), 11.13 (запрет уничтожения), 11.23 (защита архивов) помечены `confidential` в `config.yaml → access_overrides` | Без закрытых фрагментов фильтр доступа нечем показать. Выбраны пункты, которые относятся к информационной безопасности. Это настройка, её меняют без правки кода |
| D-06 | Водяной знак «УЧЕБНЫЙ ПРИМЕР…» в PDF вставляется в текст посимвольно | Символы с повёрнутой матрицей (`matrix[1] ≠ 0`) отбрасываются до извлечения текста | Без этого в тексте появляется мусор вида «М/О/Т/Н/Е» |
| D-07 | Восстановление абзацев и списков из PDF | Начало абзаца определяется по отступу первой строки и маркеру «•»; номер пункта принимается, только если он больше предыдущего | Пункт 8.12.8 в PDF набран без отступа. Проверка порядка номеров защищает от ложных совпадений. Выборка из 10 пунктов сверена в `tests/test_core.py::test_sample_points` |
| D-08 | Размер чанков | Один пункт или подпункт = один чанк. Длинные пункты (>1400 символов) делятся по абзацам с повтором вводной фразы. Глоссарий п. 1.4 делится по одному определению на чанк | Вопрос «что такое ЭКД» должен находить конкретное определение, а не весь п. 1.4 (3,9 тыс. символов) |
| D-09 | BM25 | Своя реализация на ~40 строк (`app/retrieval/search.py`) со стеммингом усечением основы вместо `rank_bm25` | Кроме BM25-ранжирования нужна метрика «доля терминов запроса, найденных во фрагменте» для калиброванного процента. Это меньше зависимостей, и `rank_bm25` такой метрики не даёт |
| D-10 | Процент релевантности и порог | `релевантность = 0,8·норм(cos) + 0,2·покрытие_терминов`, где `норм(cos) = (cos−0,40)/(0,68−0,40)`, обрезанное в [0,1]. Порог ответа `min_relevance = 0,50` (`config.yaml`) | Порог подобран сеткой на eval-наборе: ответы ≥ 0,53, вопросы вне базы ≤ 0,33, порог выбран строже середины. Контрольная выборка (12 вопросов, добавлена после настройки) проходит 12/12 |
| D-11 | Матрица визирования «CSV/JSON + pandas» | Матрица разбирается в JSON-таблицу (`storage/matrix.json`, версии), поиск строки и согласующих — чистым Python. pandas не используется | Таблица из 10 строк, и pandas не даёт выигрыша. Детерминированность («из матрицы кодом») соблюдена |
| D-12 | «Сроки из матрицы» (указание пользователя) | В Матрице сроков нет. Сроки рассмотрения (п. 10.3) и исполнения (п. 6.6) **разбираются кодом из текста пунктов базы знаний** и выбираются по виду документа. Если вид неизвестен, бот задаёт уточняющий вопрос | Сроки не зашиты в код: при новой редакции Инструкции они обновятся после ingest |
| D-13 | Формат ответа (указание пользователя) | Сначала цитата найденного пункта, затем «Простыми словами» от модели, затем источники (документ, редакция, дата, пункт, глава), которые формирует код. Пояснение строится **только по лучшему пункту** и проверяется (`app/llm/guard.py`): числа и номера пунктов — только из фрагмента, новые имена, термины через дефис и расшифровки аббревиатур запрещены, вывод о допустимости («нельзя», «не допускается») — только если во фрагменте есть такая норма, доля слов из фрагмента и вопроса ≥ 55 %. Если проверка не пройдена, показывается только текст пункта | На скриншотах первой версии модель, смешав два пункта, рекомендовала «регламент взаимодействия» вместо распоряжения, а в другом ответе расшифровала ЭКД как «экспорт-контракт» |
| D-14 | Классификация намерений | Правила и ключевые слова (`app/dialog/intents.py`). LLM вызывается, только если ни одно правило не сработало; ответ модели принимается, если он входит в список допустимых меток | Указание пользователя |
| D-15 | Учёт контекста диалога | Переформулировка кодом: короткое уточнение («а если вечером?») или местоимение («с кем **его** согласовать?») дополняется предыдущим вопросом | Слабая модель плохо переформулирует. Правило прозрачное и проверяемое |
| D-16 | Шаблоны docxtpl | docxtpl-шаблоны **собираются автоматически из исходных модулей** (`app/templates/render.py`) по разделу `layout` YAML-описания: абзац с линиями заменяется текстом с тегами Jinja, оформление модуля сохраняется. По п. 3.3 метод. рекомендаций удаляются гриф «УТВЕРЖДАЮ», пометка «МОДУЛЬНЫЙ ДОКУМЕНТ» и примечания, зоны «НЕ УДАЛЯТЬ» (дата/номер, ЭП) остаются | При обновлении модуля в `data/` шаблон пересобирается сам, и вручную поддерживать копию не нужно |
| D-17 | Падежи в шаблонах | Морфологический движок не используется. В вопросе указан нужный падеж («в дательном падеже») и приведён пример | pymorphy усложнил бы решение, а падеж в документе — ответственность исполнителя, который сверяет черновик (п. 4.1 метод. рекомендаций) |
| D-18 | Согласующие в шаблоне | Подставляются из Матрицы по `matrix_row`. Условные визы (ДИБ, ДИТ) уточняются отдельным вопросом «да/нет» и отражаются в итоговом списке | «Заранее подставлять то, что можно вывести» (PLAN.md, этап 5) |
| D-19 | Проверка загруженного документа | Правила для приказов и распоряжений: «ПРИКАЗЫВАЮ:»/«ОБЯЗЫВАЮ:», линии, номера примечаний, гриф, контроль, сроки, формат дат, подпись, шрифт, кегль, поля, а также подсказка о пояснительной записке и визах по Матрице | PLAN.md: «достаточно одного-двух типов» |
| D-20 | Веб-интерфейс и FastAPI | Chainlit (чат, кнопки, источники в боковой панели, загрузка и скачивание файлов) и FastAPI-роуты в том же сервере: `/api/ask`, `/api/health`, `/api/kb/*`, `/api/news`, `/api/me`, `/api/admin/*`, `/login`. Корневой адрес `/` — макет портала с поп-ап виджетом на iframe, сам чат — `/?chat` | Один процесс и один порт, запуск одной командой |
| D-21 | Исходящий трафик из браузера | Фронтенд Chainlit по умолчанию грузит шрифты Google и KaTeX с CDN. Внешние ссылки вырезаются middleware, шрифты отключены через `public/theme.json` | Требование «никакого исходящего трафика». Проверено `tests/ui_demo.py`: 0 внешних запросов |
| D-22 | Роли и вход | Учётная запись у каждого сотрудника (`storage/users.json`, хеши PBKDF2), вход через `password_auth_callback` Chainlit. Роль задаётся в учётной записи и читается из неё на каждом запросе. Выбор профиля в UI убран. Роли две — «Сотрудник» и «Администратор» (промежуточная «Эксперт ДОУ» убрана по решению заказчика). Администратор ведёт учётные записи в админ-панели и может включить поиск по архивным редакциям | Сначала роли выбирались профилями чата без входа (по PLAN.md, «в продакшне — SSO»). Для работы на общем сервере нужны отдельные учётные записи. Роль не хранится в токене, поэтому блокировка и смена роли действуют сразу |
| D-23 | Ingest при работающем сервере | Chroma кэширует индекс в процессе. Когда реестр версий меняется, сервер пересоздаёт клиент Chroma и подхватывает новую версию без перезапуска | Найдено при проверке: после `ingest.py` сервер отдавал старую редакцию |
| D-24 | Версия и дата документов | Инструкция: ред. 1.0, действует с 01.11.2026 (п. 12.11). У Матрицы и метод. рекомендаций дат нет, принята та же дата | Даты задаются в `config.yaml` или ключом `--date` |
| D-25 | Нумерация в метод. рекомендациях | В п. 4.2 перечень идёт «1, 3, 4» (шаг 2 пропущен). Воспроизводится как в оригинале | Источник не исправляем |
| D-26 | «Куда обратиться» | Телефонов и адресов в Инструкции нет. Бот называет подразделение со ссылкой на пункт (Департамент ДОУ — п. 2.1, 4.1.3; доступ к ИИС ДО — ДИБ, п. 2.5; кадровые вопросы — п. 9.6) и указывает, что контакты публикуются на портале (п. 12.10) | Не выдумывать контакты |
| D-27 | Коммиты | Код писался одним проходом (часть времени сеть была недоступна, и установить зависимости было нельзя). Коммиты разбиты по этапам плана после реализации, каждый этап проверен | Требование «коммит после каждого этапа» соблюдено по содержанию, но не по времени |
| D-28 | Модели в `docker-compose.yml` | Имена моделей в сервисе `ollama-init` указаны явно | В Compose нельзя прочитать `config.yaml`. При смене модели нужно поправить обе строки (отмечено в README) |
| D-29 | Где хранятся новости | `storage/news.yaml`, правятся в админ-панели. `news.yaml` репозитория — начальное наполнение: копируется при первом запуске | Правки на сервере не конфликтуют с `git pull`, новость публикуется без выкатки |
| D-30 | `ingest.py --all` при запуске | Документ, который уже есть в реестре (с действующей редакцией или отключённый), пропускается | Иначе `run.sh` при каждом перезапуске делал бы действующей редакцию из `config.yaml` поверх загруженной позже (через админ-панель или `--version`) и включал бы отключённый документ |
| D-31 | Новые документы без правки конфигурации | Админ-панель → «Добавить документ»: `doc_id` = `doc_<8 hex>`, файл в `data/uploads`, описание источника — в реестре версий (`registry.json → source`), парсер `auto` | Ключевое ограничение «подключение новых источников данных». Регламенты организации не обязаны быть размечены как Инструкция, поэтому есть парсер `plain` (пункты «N.M.» + фрагменты по разделам). `auto` берёт структурный парсер, только если тот охватил ≥ 80 % текста: иначе текст вне пунктов потерялся бы |
| D-32 | Отключение документа | Действующая редакция уходит в архив, документ пропадает из поиска и с портала; Матрицу отключить нельзя | Обратимо («Сделать действующей»), без удаления из индекса. Матрица нужна коду согласований |
| D-33 | Оригиналы документов и роли | Оригинал целиком — только роли, которой доступны все уровни документа, включая `access_overrides` | Иначе закрытые пункты, скрытые фильтром в поиске, читались бы в скачанном PDF. Отдельной «редакции для сотрудников» в исходных материалах нет |
| D-34 | Черновики | Скачивание через API — только автору (логин в `*.owner`), случайная часть в имени, удаление через 24 ч | В черновике ФИО и должности. Имя `шаблон_время` подбиралось перебором |
| D-35 | Модель вне внутренней сети | `llm.base_url` с внешним адресом — ошибка запуска, если не задан `llm.allow_remote: true` | Ограничение «защита корпоративных данных при использовании LLM»: ошибка в `.env` не должна отправить базу знаний во внешний сервис. Имя без домена (`ollama` в Docker) считается внутренним |
| D-36 | ПДн и модель | Текст сотрудника маскируется (`app/security/pii.py`) перед вставкой в промпт; фрагменты базы знаний — нет | Модели ФИО и телефоны для ответа не нужны. Маскирование фрагментов исказило бы реквизиты документов (номера, даты актов) |
| D-37 | Виджет для портала организации | `widget.js` (Shadow DOM, iframe на `/?chat`), `frame-ancestors` из `portal.embed_origins`, cookie остаётся `SameSite=Lax` | Встраивание «одной строкой» стало реальным, а не обещанием. `SameSite=None` ослабил бы защиту от CSRF; портал организации на том же домене получает cookie и с Lax, для другого домена нужен SSO |
| D-38 | Срок входа | 12 часов вместо 15 дней по умолчанию Chainlit | Рабочий день; украденный или забытый на чужом компьютере токен живёт недолго |
| D-39 | Лента новостей и доступ | Автоновости — только по документам, доступным роли; номера закрытых пунктов убираются | Иначе лента раскрывала бы название закрытого документа и какие закрытые пункты изменились |
