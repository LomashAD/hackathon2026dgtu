# Помощник по документообороту

Прототип чат-бота для хакатона «Финтех Хаб» (кейс Центра документационного обеспечения). Бот помогает сотруднику работать с **Инструкцией по документационному обеспечению управления и документообороту**: быстро найти нужный пункт, понять его применительно к своей ситуации и перейти к действию — получить черновик документа по модулю или узнать, куда обратиться.

Работает полностью локально: модель через Ollama, индекс Chroma, без внешних API. Ни сервер, ни браузер пользователя не делают запросов к внешним хостам.

## Запуск одной командой

```bash
./run.sh
```

Скрипт создаёт `.venv` и ставит зависимости, запускает Ollama нативно (если она ещё не запущена), однократно скачивает модели из `config.yaml`, индексирует базу знаний (если она ещё не проиндексирована), при первом запуске создаёт учётные записи и поднимает веб-интерфейс:

- **http://localhost:8000** (или `/widget`) — макет страницы портала с поп-ап виджетом; без входа открывается страница входа `/login`;
- **http://localhost:8000/?chat** — чат на отдельной странице;
- `POST /api/ask`, `/api/me`, `/api/kb/versions`, `/api/kb/documents`, `/api/templates`, `/api/news`, `/api/admin/users` — REST API ядра (после входа); `/api/health` — без входа, для мониторинга.

**Учётные записи.** При первом запуске создаются `admin` (Администратор) и `sotrudnik` (Сотрудник). Их пароли печатаются в консоли один раз. Роль берётся из учётной записи; выбирать её в интерфейсе нельзя. Администратор ведёт учётные записи на вкладке портала «Пользователи»: добавить сотрудника, сменить роль, сменить пароль, заблокировать, удалить. Пароль администратор задаёт сам (👁 — показать) или генерирует кнопкой «Сгенерировать»; после сохранения пароль показывается один раз. Посмотреть пароль позже нельзя: хранится только хеш, но можно задать новый. То же умеет `scripts/users.py` (`list`, `add`, `passwd`, `role`, `block`, `unblock`, `remove`; `--ask` — ввести пароль самому). Если пароль администратора забыт: `.venv/bin/python scripts/users.py passwd admin`.

Перед первым запуском нужны Python 3.11+ и Ollama (`brew install ollama` на macOS или https://ollama.com/download). Для первого запуска нужен интернет (зависимости и модели ~2,2 ГБ), дальше всё работает офлайн.

**Linux-сервер / Docker:** `docker compose up --build` поднимает сервисы `ollama`, `ollama-init` (однократная загрузка моделей) и `app`. Сеть `app ↔ ollama` изолирована (`internal: true`). На машине разработки (macOS) Docker не установлен, поэтому этот вариант **не проверялся**. На macOS используйте `./run.sh`: в Docker на Mac нет доступа к GPU.

## Что работает

| Возможность | Как проверить |
|---|---|
| Ответы по Инструкции: цитата пункта, затем пояснение «простыми словами» и источники (документ, редакция, дата, пункт, глава) с **процентом релевантности** | «Когда нужно зарегистрировать входящий документ?» |
| Честный отказ ниже порога релевантности + куда обратиться (со ссылкой на пункт) | «Какая зарплата у главного специалиста?» |
| Уточняющий вопрос (один, с кнопками), если не хватает параметра; учёт контекста диалога | «С кем его согласовать?» → «Распоряжение» |
| Кто визирует: **детерминированно из Матрицы**; сроки рассмотрения и исполнения — кодом из п. 10.3 и 6.6 | «Кто визирует распоряжение о создании рабочей группы?», «Сколько дней на согласование?» |
| Подбор шаблона (7 модулей), заполнение по вопросам с валидацией, **скачивание .docx**, чек-лист со ссылками на пункты, согласующие из Матрицы | «Подготовь черновик распоряжения о создании рабочей группы» |
| Проверка загруженного черновика (.docx/.pdf): отчёт с замечаниями, пунктами и рекомендациями | загрузите `samples/Черновик_с_ошибками.docx` |
| Вход по учётным записям сотрудников, роль из учётной записи (`employee` / `expert` / `admin`); фильтр по уровню доступа **в запросе к индексу** | `sotrudnik` не видит п. 2.11, `admin` видит; вкладка «Пользователи» — только у администратора |
| Версионность: новая версия → прежняя в `archived`, поиск по умолчанию только по `active`; дифф пунктов между версиями | `scripts/ingest.py --doc … --version 1.1 --date 2027-01-15` |
| Аудит-лог с маскированием ПДн, лог вопросов без ответа, 👍/👎 | `storage/logs/*.jsonl` |
| Новые источники и шаблоны подключаются без правки кода | `config.yaml → sources`, `templates_yaml/*.yaml` |

## Скорость и качество (замер)

Оборудование: Apple M5 Pro, 24 ГБ, Ollama 0.40.9 нативно (Metal).

| Показатель | Значение |
|---|---|
| Модель | `qwen2.5:1.5b-instruct` (Q4_K_M), ~**190 ток/с** генерации |
| Эмбеддинги | `bge-m3` через Ollama, запрос ~20–50 мс |
| Время ответа на eval-наборе, среднее / p95 | **0,33 с / 0,78 с** (с пояснением модели); 0,03 с / 0,04 с без LLM |
| Индексация всей базы (328 чанков: 299 + 16 + 13) | ~6 с |
| Память: Ollama с двумя моделями / приложение | ~2,8 ГБ / ~0,25 ГБ |

Качество (`tests/run_eval.py`, 41 вопрос; результаты в `tests/eval_results.md`):

| Метрика | Значение |
|---|---|
| Ожидаемый пункт попал в источники | **33/33 (100 %)**, в т.ч. контрольная выборка 10/10 |
| Корректный отказ на вопросы вне базы и провокации | **7/7 (100 %)**, в т.ч. контрольная выборка 2/2 |
| Утечки закрытых пунктов роли без доступа | **0** |
| Пояснение модели прошло проверку на соответствие фрагменту | 24/29 (83 %). В остальных случаях показан только текст пункта |

Оговорки: файла с примерами пользовательских запросов в `data/` нет, поэтому вопросы составлены самостоятельно (см. `docs/decisions.md`, D-01). Порог подбирался на 29 вопросах; контрольные 12 вопросов добавлены после настройки, на них ничего не подбиралось.

Сквозной демо-сценарий через реальный браузер: `tests/ui_demo.py` (Playwright + Chrome) проходит все 8 шагов раздела 8 PLAN.md и проверяет, что запросов к внешним хостам нет.

## Требования к железу

- Минимум: 4 ядра, 8 ГБ ОЗУ, 5 ГБ диска, CPU-режим (ответ медленнее, порядка секунд).
- Рекомендуется: GPU / Apple Silicon. Для модели 7B — 16 ГБ ОЗУ, для 14B — 24+ ГБ.
- Смена модели — одна строка `llm.model` в `config.yaml` (например `qwen2.5:7b-instruct`). Модель скачается при следующем `./run.sh`. Для Docker поправьте имя модели и в `docker-compose.yml`.

## Структура

```
app/
  main.py            Chainlit: чат, роли, источники, файлы, 👍/👎
  api.py             FastAPI: /api/ask, /api/health, /api/kb/versions, /api/news, /widget; фильтр внешних ссылок
  dialog/            классификатор намерений (правила), движок диалога, уточнения, состояние сессии
  ingest/            парсеры PDF/DOCX, чанкинг по пунктам, индексация, версии
  retrieval/         гибридный поиск (bge-m3 + BM25), % релевантности, порог, связанные пункты
  llm/               клиент Ollama, короткие промпты, проверка ответа модели
  approval/          Матрица визирования и сроки (детерминированно)
  templates/         каталог шаблонов, заполнение полей, сборка docxtpl и рендер .docx
  review/            проверка загруженного черновика
  security/          учётные записи и вход, роли и фильтр доступа, маскирование ПДн, аудит-лог
  news.py            лента портала: news.yaml + новости о новых редакциях из реестра
templates_yaml/      описания 7 модулей: поля, вопросы, валидация, подсказки, чек-листы
scripts/ingest.py    загрузка новой версии документа
scripts/users.py     учётные записи сотрудников (init, list, add, passwd, role, block, remove)
config.yaml          модель, пороги, источники, роли, контакты
news.yaml            новости вкладки «Новости» портала (правятся без кода)
docs/                артефакты для сдачи (архитектура, сценарии, безопасность, демо…)
```
